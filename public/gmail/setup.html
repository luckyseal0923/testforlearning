第一次，連接你的 Gmail。

網站已準備好寄信功能。初次使用要建立自己的 Google 應用識別碼，讓 Google 知道是誰、從哪個網站要求授權。這個範例使用瀏覽器彈出視窗授權，不需要 Client Secret、API Key 或應用程式密碼。

1. 啟用 Gmail API

開啟 Google Cloud Console，建立或選擇專案，再到 Gmail API 按「啟用」。

2. 設定 Google Auth Platform

  1. 在 Branding 設定應用名稱，例如「我的 Gmail 寄信練習」，填寫自己的支援及聯絡信箱。
  2. 個人 Gmail 帳號在 Audience 選 External，維持 Testing，並在 Test users 加入自己將登入的 Gmail。組織的 Workspace 帳號則依管理員政策設定。
  3. 在 Data Access 加入這兩個 scope：
    https://www.googleapis.com/auth/gmail.send
    https://www.googleapis.com/auth/userinfo.email

3. 建立 Web application 的 Client ID

到 Clients → Create client → 選 Web application。在 Authorized JavaScript origins 加入：

https://luckyseal0923.github.io

只填協定及主機，不要加入 /testforlearning/gmail/ 路徑。若也要在預設連接埠做本機測試，另加：

http://localhost
http://localhost:3000

使用其他本機連接埠時，請加入對應的 origin。此範例使用彈出視窗流程，不需要新增 Redirect URI。

4. 回到網站貼上 Client ID

複製以 .apps.googleusercontent.com 結尾的 Client ID，貼到寄信頁的設定欄，按「儲存連線設定」，再按「連接 Google 帳號」。Client ID 是公開識別碼；此頁沒有密鑰輸入欄。

5. 寄出第一封測試信

登入後按「寄給自己」，填寫主旨與內容 → 預覽信件 → 確認寄出。收到 Gmail API 的寄送回覆後，頁面會顯示結果。到自己的 Gmail 寄件備份與收件匣確認，才算完成實際測試。

遇到狀況時

  • 連接按鈕無法按：先儲存 Client ID，並確認 Google 登入元件已載入。
  • Origin 不符合：檢查 Authorized JavaScript origins 是否和寄信頁顯示的 origin 完全相同。Google 設定變更可能需要一段時間生效。
  • Access blocked 或 access_denied：確認登入帳號已列入 Test users；受管理的 Workspace 帳號可能需要管理員允許。
  • Google 未驗證應用程式：本練習維持 Testing 並限自己的測試帳號使用。若要提供給其他人，請依 Google 的要求完成應用審核。
  • 授權到期：重新連接後再預覽、寄出；網頁不會自動重新授權或重送信件。
  • 結果未確認：先查看寄件備份，確認是否已寄出，再決定是否重新操作。

這是什麼類型的網站？

這個頁面是 GitHub Pages 上的靜態前端。Google 負責授權與 Gmail 後端寄信，因此靜態網頁也能串接真實服務。它需要使用者開著頁面並點擊寄送，不提供排程或背景自動寄信。
