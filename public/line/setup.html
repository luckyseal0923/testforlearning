SETUP · ONE STEP AT A TIME

先接好後端，
再送第一則通知。

前台在 GitHub Pages；LINE 的密鑰與接收程式在 Supabase。

1. 使用獨立的 Supabase 練習專案

在專案的 SQL Editor 貼上本專案的 資料表 SQL，執行一次。這會建立收件人、一次性綁定碼與事件去重資料表，並啟用 RLS。只有後端能讀寫，公開網頁無法直接查看 LINE 識別碼。

這是單一管理者的練習範例，管理金鑰可管理這個練習專案的全部收件對象。

2. 準備新的 LINE 官方帳號

  1. 在 LINE Official Account Manager 建立練習帳號。
  2. 到「設定 → Messaging API」啟用，選擇自己的 Provider。
  3. 進入 LINE Developers 的該 Channel，取得 Channel secret 與 Channel access token。
  4. 要通知群組時，開啟「Allow bot to join group chats」。

密鑰只填到下一步的 Supabase Secrets。不要放在網頁、GitHub、綁定指令或 Webhook 網址中。

3. 設定 Supabase Secrets

到 Supabase 專案「Edge Functions → Secrets」設定：

名稱內容
LINE_CHANNEL_SECRETLINE Channel 的 secret
LINE_CHANNEL_ACCESS_TOKENLINE Channel 的 access token
APP_ADMIN_KEY自己產生、至少 32 字元的隨機管理金鑰
APP_ALLOWED_ORIGINShttps://luckyseal0923.github.io

要在本機練習，可把網站來源設成 https://luckyseal0923.github.io,http://localhost:3000。來源只包含通訊協定、主機、連接埠，沒有頁面路徑。

產生隨機管理金鑰的本機指令（請自己妥善保存輸出）：

node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"

SUPABASE_URL 與 SUPABASE_SERVICE_ROLE_KEY 是 Supabase Hosted Edge Functions 預設提供的後端環境變數，不需貼到前台。

4. 部署接收程式

在電腦專案資料夾的終端機執行，將「你的專案代號」換成 Supabase Project URL 中的代號：

npx supabase login
npx supabase link --project-ref 你的專案代號
npx supabase functions deploy line-practice --project-ref 你的專案代號 --no-verify-jwt

後端原始碼在 supabase/functions/line-practice。只為這個函式停用平台的 JWT 預檢：Webhook 仍會檢查 LINE 簽章，管理功能仍會檢查管理金鑰。

5. 連線並驗證 Webhook

  1. 回到練習頁，填入自己的 Supabase Project URL 與管理金鑰，按「連接後端」。
  2. 複製出現的 Webhook URL，填到 LINE Developers → Messaging API → Webhook settings。
  3. 按 Verify，應顯示 Success，再啟用 Use webhook。這一步不會發送通知。

網址格式為：

https://你的專案代號.supabase.co/functions/v1/line-practice/webhook

網址是接收地址，不是發送憑證；可以公開，但後端會驗證每次請求的 LINE 簽章。

6. 綁定、預覽、確認發送

  1. 管理頁填收件名稱，選個人或群組，產生綁定碼。
  2. 個人先加 Bot 好友，再把整行綁定指令私訊 Bot；群組先邀請 Bot 入群，再在群組傳送指令。
  3. 綁定碼有效 10 分鐘、只能使用一次。傳送後回管理頁，按「重新整理名單」確認。
  4. 選擇收件人、填入測試訊息，按「預覽通知」。
  5. 確認收件人與內容後按「確認發送」，再到 LINE 查看。LINE 接受請求不代表對方一定收到或已讀。

只有你在網頁按「確認發送」才會傳送通知。一般聊天不會自動回覆，也不會保存聊天內容。對方封鎖 Bot 或 Bot 離開群組後，收到對應事件會停用該收件對象。

常見狀況

  • 連不上：確認部署成功、管理金鑰相同、網站來源正確。
  • Verify 失敗：確認網址尾端是 /webhook、LINE secret 屬於同一個 Channel，並停用這個函式的 JWT 預檢。
  • 名單沒有更新：確認 Bot 加入正確群組、綁定碼未過期，類型選對；不需把一般 LINE 好友 ID 貼進網站。
  • 發送失敗：確認 Channel access token 有效、Bot 仍在群組內，並查看 LINE 訊息額度。
  • 發送結果不明：先到 LINE 查看，不要重新整理後重送；同一頁的「重試同一筆」會沿用同一個去重識別碼。
